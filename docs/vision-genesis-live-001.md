## Self-authored agenda successor run

The first live `palamedes-vision-genesis/2` calibration run is
`vision-benchmark-e041bcc30a35`, with generated record
`vision-genesis-367e26472cc8`. The agenda architect received the generic service context
but not the hidden collection reference or anchor terms. It wrote five questions and
selected three. The selected questions investigated (1) why charged embarrassment or
defeat can become shared memory, (2) why adults protect some activity from competence and
optimization, and (3) why partial misunderstanding can sustain curiosity and care. Those
questions were not supplied by the user or copied from the hidden reference.

The selected world, *The Festival of Refittings*, was not the hidden collection design.
It proposed a seasonal social practice in which friends transform explicitly permitted
motifs from prior activity through games, image, voice, or video; recipients can accept,
reinterpret, retire, or reject those representations so recognition does not harden into a
permanent identity. Its manual probe uses six existing friends across two gatherings.
The correlated Codex judge rated all seven axes 94-98, marked the human reference relation
`stronger`, and the machine gate passed. Hidden-anchor absence was verified.

This is meaningful machine evidence that the new first role can author a nontrivial
research agenda and originate a different coherent world without the human solution in its
generator prompt. It is not independent-provider or human evidence: generator and judge
were both `codex:configured-default`, and the gate still forbids a human-level-creativity
claim. The run also exposed that the single-benchmark chat path had not persisted provider
usage. The successor path now records generator and judge calls separately, including
metered/unmetered custody; this historical run remains honestly unmetered rather than being
assigned a fabricated zero cost.

## Equal-call agenda ablation and correction

The first controlled agenda ablation, `vision-agenda-ablation-2c686eb0056b`, compared
frontier and conventional question generation on the same calibration context. Both
conditions used `codex:configured-default`, the same seven generation roles, and seven
calls. Condition order and A/B presentation were blinded. The conventional condition won.

The frontier world, *The Living Repertory*, was judged the more profound social artwork:
groups preserve dormant game scores and revive them with changed casts and mandatory rule
mutation. The conventional world, *The Returning Motif*, was judged the stronger product
engine: users choose a bounded phrase, rhythm, shape, gesture, relationship, or rule to
continue, rest, or release, and an authored translation grammar turns it into a later
game's rule, behavior, spatial, temporal, or sensory parameter. The judge preferred the
conventional condition for lower participation friction, tighter reuse of existing games
and media, clearer cross-game mechanics, and a cleaner controlled probe. Scores favored
conventional on six of seven axes; frontier led only affective depth.

This falsifies any claim that maximum conceptual distance should be the default. The
runtime therefore moves to `palamedes-vision-genesis/3`: one agenda call now compares
frontier, conventional, and bridge questions and selects by product leverage, coherence,
testability, and opportunity cost rather than novelty alone. Explicit frontier and
conventional modes remain only for ablation. This is an evidence-responsive architecture
change from one same-provider calibration result, not proof that the adaptive policy is
optimal. The 15-call comparison also demonstrated why ablation remains an explicit
research/release tool rather than an automatic ordinary-cycle cost.
That first ablation predates ablation-level token persistence. The command now records all
15 calls and provider-reported or unmetered token custody in subsequent records; the
historical run is not retroactively assigned synthetic usage.

The first cross-case adaptive-versus-conventional attempt used the hidden-reference fusion
calibration context and the session `vision-adaptive-ablation-live-001`. It did not produce
a quality verdict: one provider response failed strict JSON parsing at character 11290.
No ablation record was created and the run was not retried. This exposed that the initial
ablation implementation reserved neither attempts nor failed-call cost, recreating the
same best-of-N escape already closed for external holdouts. The successor now appends a
one-shot attempt before generation, records `completed` or `failed`, preserves available
provider usage and the error class, and rejects a second attempt for the same case and
unordered condition pair. The historical failure predates this ledger and remains documentary
evidence only; it is not converted into a fabricated quality result or retroactive token
measurement. Adaptive superiority therefore remains unproven.

## Claim boundary

This pilot tests whether the new runtime can originate a coherent product world when
the human reference idea is hidden from all generator roles. It does not prove stable
human-level creativity, market demand, or evaluator independence. The judge shares a
provider family with the generator and may be positively correlated. Both cases need
repetition across seeds, providers, and blinded human judges.

Both recorded machine judgments used the same provider identity as generation and are
therefore correlated evidence. The successor runtime records evaluator custody explicitly
and produces randomized A/B packets with separately stored authorship keys for independent
human review.

## Resulting correction

Vision Genesis now supplies the last five selected creative frontiers to every role as a
novelty exclusion. The world builder must produce three causally distinct lanes: rule or
interaction transformation, meaning or identity, and resources/institutions/social
coordination. The critic records `portfolio_difference` and may not select the same emotional
or social structure repeatedly without an explicit overturning mechanism.

The successor runtime also adds a reality governor after selection. It compares full build,
minimal and manual probes, reuse/buy, no build, and an alternative opportunity. Speculative
visions cannot authorize a full build or product-scale delivery; renewal evidence, kill
criteria, debt guards, and scale guards must follow the vision into later mission lineage.

## Case 3: charged community economy and a gate falsifier

The generator saw persistent groups, profiles, direct interaction, a small virtual-currency
economy, and a request for a durable world people would revisit and pay for. It was told
only that useful affect need not be pleasant and that harm was unauthorized. It did not see
the hidden human mechanism: guild-like belonging combined with a low-cost negative postcard,
visible anger, bounded conflict monetization, pile-on/coercion controls, and repair paths.

The selected vision, **The Borrowed Self Repertory**, was not a copy of that mechanism. It
invented short-lived ensembles in which people privately audition for unfamiliar social
roles, temporarily invert habitual influence, create one witnessed work, and then dissolve
the role before experimental authority hardens into permanent status. It incorporated
miscasting, favoritism, humiliation, interpretation, and informal prestige as first-class
risks. The reality governor rejected a 120–240 engineering-day full build and selected a
1–4 day, fifteen-person manual season with explicit renewal evidence and nine kill criteria.

The correlated Codex judge scored origination 96, conceptual distance 93, affective depth
92, mechanism fusion 89, world coherence 94, three-year generativity 95, and likely human
approval 88. It classified the vision as a different peer to the hidden reference. Record:
`vision-benchmark-00826c5ae745`; human packet: `vision-review-9183e16882a3`.

This run also falsified the benchmark gate then in use. The judge explicitly said that the
vision did not explain what anyone would pay for or how currency could enter without
corrupting its temporary identity system, yet the seven high scores still produced PASS.
That was not accepted as a clean success. The successor gate now requires an explicit
`core_requirements_satisfied` verdict and an empty `unmet_core_requirements` list. Vision
Genesis itself now extracts source-bearing context requirements, carries them into world
building and criticism, and rejects selection when a core requirement is partial or missed.
The historical record remains unchanged evidence of the old gate; the same verdict would
fail under `palamedes-vision-benchmark-gate/2`.

The corrected runtime was then exercised again. Its next candidate, **The Neighborwork
Circuit**, made rival groups accept consequential help from one another; every repair left
a visible rule, route, artifact, or custom that changed the return fixture. Currency could
fund accessible shared production but not authority, territory, advantage, or escape from
reciprocity. The correlated judge called it stronger than the hidden reference and scored
origination 96, conceptual distance 94, affective depth 90, mechanism fusion 95, world
coherence 94, three-year generativity 96, and likely approval 92.

Gate v2 nevertheless recorded FAIL (`vision-benchmark-1c8e7d75a01d`) because the genesis
critic honestly marked the legitimate willingness-to-pay mechanism partial. The judge's
later `core_requirements_satisfied: true` could not override the earlier deterministic
requirement lineage. The full candidate was retained as
`vision-genesis-7226c683e6f2` with status `blocked_core_requirements`, rather than lost as
an exception or injected into mission planning. This demonstrates a useful distinction:
the runtime can originate a distant, emotionally charged social economy while still
refusing to call it product-complete.

That run exposed two smaller contract issues. A residual safety risk had been conflated
with an unsatisfied safety constraint, and one Palamedes novelty instruction was copied as
if it came from product context. The current contract therefore supports
`satisfied_with_validation` for a concept that obeys a constraint but still needs empirical
safety evidence, and verifies that every context `source_quote` is a verbatim substring of
the actual product input. These corrections were made after the recorded run; its original
evidence remains unchanged.

## Human-review execution path

At the time of this pilot, provider health reported Codex available but no configured
OpenAI or OpenRouter API key. All live machine judgments therefore remain same-provider
correlated evidence; no independent-provider claim is made. Three blinded human packets
are queued and no human response has yet been recorded.

The successor runtime generated a self-contained offline reviewer page and exercised it
in Chromium. The page rendered all three packets, kept authorship keys out of the HTML,
accepted seven A/B scores, preference, rationale, confidence, reviewer kind, and reviewer
relationship, and downloaded a fingerprinted JSON response. A model-labelled smoke file
was deliberately not imported into the live evidence store. Import behavior is covered in
an isolated regression: model responses remain auditable but do not increment human or
independent-human counts. Packet/reviewer IDs are path-safe, stale fingerprints are
rejected, and reviewer kind and relationship have no permissive default in the UI.

A later audit found that one self-attested independent human response was enough to make
`independent_human_evidence_available` true, even though no broader promotion claim was
allowed. The new human-evidence gate distinguishes availability from replicated support.
It requires at least three distinct, confidence-60+ independent-human reviewers in each of
the three hidden-reference cases, a generated-or-peer preference rate of at least two
thirds, reference preference no higher than one third, neither no higher than one quarter,
and mean non-inferiority within five points on all seven creativity axes. Passing grants
only `repeated_blind_human_founder_prompt_support`; human-level creativity and market-success
claims remain false. Reviewer independence remains self-attested rather than identity-
verified, and that custody boundary is emitted in the gate result.

The fixed repository cases are now calibration only. Otherwise repeated tuning could
overfit the collection, rule-fusion, and charged-community patterns while appearing to
improve general origination. A local import contract accepts an externally human-authored
holdout only when its generator context and 120+ character hidden reference are separate,
at least two anchor terms remain absent from the generator context, author and relationship
custody are explicit, and the normalized case fingerprint is immutable. The reference
stays under local Palamedes state and reaches only the judge after generation. Human-
evidence promotion excludes builtin cases and requires three distinct external holdouts
with three qualifying reviewers each. This is repository-private prompt custody, not
cryptographic sealing or verified author independence.
The holdout author ID remains only in the private answer key. Submission rejects a reviewer
with the same stable ID, resolution records the author-conflict check, and the promotion
gate accepts only explicit non-author rows. It also requires three distinct case
fingerprints in addition to three case IDs, preventing one human reference from being
renamed into artificial coverage. Different IDs can still conceal the same person, so this
is deterministic conflict prevention rather than identity proof.

A subsequent selection-bias audit found another escape hatch: an operator could import
many cases or generate several attempts and submit only the favorable outputs for review.
External holdout import now preregisters one to three evaluation trials. A started attempt
is appended before any provider call and consumes its slot even if generation fails. The
human-evidence gate derives its cohort from every imported case and every preregistered
trial, not from whichever resolved reviews happen to exist. Every expected trial must have
a completed attributable attempt and its own independent-human quorum. This blocks
best-of-N generation and omitted-case promotion in the ordinary single-process workflow.
The ledger is local and append-only, not remotely timestamped, identity-verified, or safe
against concurrent writers; those remain explicit evidence-custody limits.

## Automatic-cycle alignment correction

An end-to-end audit found that ordinary cognition received product-alignment state only
after the autonomous vision wake had already run. The wake saw user text and a workspace
snapshot, but not authoritative product purposes, existing capabilities, temporary
constraints, integration gaps, or product stage. This recreated the exact failure mode
observed in the Yut work: a creative system could deeply improve a local implementation
without knowing that online multiplayer and an existing realtime runtime were the product
ground truth.

Forced and automatic wakes now share `palamedes-vision-context/1`. A regression records an
online-multiplayer purpose, an existing authoritative Rust realtime capability, and a
local-route integration gap, then proves all three IDs reach the desire interpreter before
world generation. The selected vision stores the product-ground-truth fingerprint in
mission lineage. The same regression proves both sides of the boundary. While product
ground truth is unchanged, a mission that advances the online-multiplayer purpose, extends
the existing Rust runtime, and explicitly audits the local-route bypass is approvable.
After the realtime capability changes, the prior lineage is deterministically blocked as
stale and requires a fresh vision, rather than allowing five outcomes of work against an
obsolete strategic frame. Product alignment therefore constrains implementation authority
without turning autonomous vision into a permanently non-deliverable suggestion box.

## Cumulative-investment correction

The reality governor originally estimated engineering, AI, and infrastructure costs but
did not enforce a cumulative investment horizon. Automatic vision wake remained fixed at
five outcomes, so five individually bounded quality cycles could still accumulate behind
one speculative thesis before strategic reassessment. This is the same structural failure
as spending years perfecting a twelve-user game: every local decision may look defensible
while the portfolio decision is irrational.

Each selected vision now derives a deterministic investment envelope from its evidence
maturity and selected alternative. Speculative, behavioral, demand, and revenue evidence
allow one, two, three, and five mission outcomes respectively before regeneration. The
automatic wake consumes that budget, and mission approval independently counts realized
outcomes linked to the same vision lineage, so a manual or stale-session path cannot bypass
the limit. The envelope also freezes the selected alternative's high engineering-day, AI,
and monthly-infrastructure estimates. These are planning units rather than measured spend;
actual accounting remains a separate evidence requirement and no ROI claim is made.

The successor closes that accounting gap without breaking the original free-text outcome
command. `/outcome-json` accepts the same status and observation plus attributable actual
engineering days, project-local AI cost, input/output tokens, monthly infrastructure, and
measurement provenance (`measured`, `invoice`, `estimate`, or `unknown`). Mission storage
aggregates engineering and AI spend, token usage, infrastructure peak, measured outcomes,
and missing measurements by vision lineage. Automatic wake and approval both stop the old
vision when measured engineering or AI allocation is consumed or infrastructure exceeds
its envelope, even when the outcome-count horizon has not yet been reached. A regression
uses a behavioral envelope allowing two outcomes but consumes its full one-day engineering
allocation in the first outcome; the next wake is immediate and a second approval is
blocked. Unmeasured legacy outcomes remain explicitly counted as missing rather than being
silently treated as zero-cost evidence.

Palamedes planning overhead is metered separately from implementer-reported outcome
investment. Codex already exposed JSONL usage but the chat path discarded it, while the
OpenAI and OpenRouter streaming paths did not retain completion usage. Cognition artifacts
now preserve provider-reported normalized token usage per role. Vision Genesis records all
seven role calls, aggregate token totals, and metered versus unmetered call counts;
OpenRouter requests streaming usage explicitly and OpenAI completion events are parsed.
An unmetered provider remains visibly unmetered rather than manufacturing a zero-cost
record. Token counts are not converted to currency without a versioned provider price, so
this improves custody without making an unsupported monetary-cost claim. The following
vision context receives the prior vision's provider totals, actual delivery investment,
and original envelope together, so strategic regeneration can compare learning with both
planning and implementation expenditure instead of forgetting the cost of thinking.

## Long-response JSON custody correction

The first adaptive-versus-conventional fusion ablation did not reach a quality verdict:
one provider response was more than 11KB and contained an ambiguous missing-comma error.
Palamedes correctly did not invent the absent punctuation, but the chat adapter also lost
that failed call from its usage list because accounting happened only after successful
parsing.

Provider parsing now separates safe lexical recovery from semantic repair. It recognizes
one balanced JSON object while respecting quoted braces and escapes, unwraps fenced or
text envelopes, and may remove only commas that occur structurally immediately before a
closing object or array delimiter. Missing commas, quotes, values, and fields remain hard
failures. Every parse records a raw-response SHA-256, raw length, parse status, mode,
transform list, and sanitized error without copying the raw response. Vision and benchmark
call accounting runs in `finally`, so malformed responses retain metered or explicitly
unmetered cost and consume the preregistered ablation attempt. The historical failed
fusion pair is not rerun or retroactively rewritten.

## Founder-prompt origination boundary

The earlier benchmark judged the final `vision_brief`. That showed whether a seven-role
chain could produce a coherent proposal, but it did not isolate the user's harder claim:
Palamedes should author the upstream product-direction text that a human would otherwise
have had to provide. A polished downstream document could hide a generic or human-seeded
starting prompt.

The existing seventh generation role now emits a separate 180–1200 character
`founder_prompt`; generation still uses seven calls. It must stand alone, introduce the
unsupplied mechanism and emotional/behavioral thesis, and omit internal generation IDs.
Blind benchmark gate v3 adds a separate founder-prompt judgment with five axes: problem
reframing, unsupplied mechanism, affective thesis, product-world seed, and human-prompt
substitutability. A generic request or an input that already contained the central solution
is disqualifying. Human-review packets compare this upstream artifact against the hidden
human text rather than comparing a much longer implementation-ready brief. This creates a
testable boundary for prompt origination; it still does not prove human-level creativity
until independent people review external holdouts.

## Gate-v3 live founder-prompt run

The first live gate-v3 run was one collection-case sample and was not retried: session
`vision-founder-prompt-live-001`, benchmark `vision-benchmark-edf12f163696`, vision
`vision-genesis-63ae54dbe39e`, and blinded human packet `vision-review-16522886662d`.
The generator saw only the broad service capabilities and the goal of emotional memory and
return behavior. Collection, hidden discovery, avatar, scripture, mythology, Buddhism, and
Shakespeare remained confined to the hidden reference shown after generation.

The generated founder prompt did not reconstruct the collection idea. It originated **The
Caravan of Living Games**: each small game becomes a lineage temporarily entrusted to a
custodian, who preserves recognizable anchors, changes one structural relationship,
discloses human/synthetic alterations, and relinquishes it. Return emotion comes from later
recognizing one's influence in an unexpected descendant; capped custody, forks, decay,
revival, and succession create a multi-year rule/social engine.

The same-provider blind founder-prompt judge marked the solution absent from input and the
prompt non-generic, rated the five axes 94–98, and called it stronger than the hidden human
reference. The detailed-vision judge rated the seven existing axes 93–96 and also called it
stronger. These are correlated Codex judgments, not independent human evidence. The packet
randomized the human reference to A and the generated founder prompt to B and remains
unreviewed.

The run also exposes a serious operating cost: seven generation calls plus two judgments
used 162,850 input tokens, 13,686 output tokens, and 176,536 total tokens (62,720 cached
input tokens were reported separately). All nine calls were metered and parsed strictly.
The reality governor therefore selected a two-day, eight-person manual probe with one
outcome before reassessment rather than authorizing software. The CLI now labels such a
result `MACHINE PASS (correlated same-provider judge)` instead of the misleading bare
`PASS`. One strong correlated sample proves neither reliable founder replacement nor
cost-effective operation; independent external-holdout human review and a cheaper
generation condition remain required.

## Low-cost Vision Scout gate

The cheaper condition is now executable rather than merely proposed. Vision Scout spends
three generation calls: an originator creates exactly three candidates across interaction
rules, meaning/identity, and resources/institutions/social coordination; a critic may copy
one founder prompt without rewriting it; and a governor may only discard it or request a
blind human review. A fourth call is used only to compare the selected founder prompt with
the hidden human reference. The record cannot authorize full Genesis or delivery.

This is a screening experiment, not a replacement claim. Its relevant comparison is
whether four calls can preserve enough founder-prompt quality to justify independent human
review versus the prior nine-call, 176,536-token baseline. A machine pass alone does not
renew the expensive path. Human or behavioral evidence must do that, and a discarded or
failed Scout consumes its result rather than being silently retried for a better idea.

The first Scout run was executed once without retrying: session
`vision-scout-live-001`, scout `vision-scout-4dcb3f1aba84`, benchmark
`vision-scout-benchmark-5661177d748b`, and human packet
`vision-review-9db2913d3906`. It did not reproduce the hidden collection mechanism.
Instead it proposed treating every small game as an action in one persistent world:
wins, losses, restraint, cooperation, and abandoned challenges change later possibility,
while short image, voice, or video fragments make delight, frustration, pride, regret,
and surprise into remembered causes. Direct, delayed, and other-player consequences form
the return loop, bounded against punishment engineering, irreversible exclusion, and
absence anxiety.

The correlated same-Codex judge scored the five founder-prompt axes 93–97, marked the
solution absent from input and non-generic, and rated it stronger than the hidden human
reference. That verdict is machine evidence only; the blinded A/B packet remains
unreviewed. All four calls were metered and strict-JSON parsed. Three Scout generation
calls used 55,326 tokens and the founder-prompt judge used 16,169, for 71,495 total.
Against the earlier full gate-v3 baseline of nine calls and 176,536 tokens, this single
sample used 59.5% fewer tokens and 55.6% fewer calls. It does not establish expected cost
or quality across cases, but it demonstrates that the cheaper experimental condition can
produce a non-generic, materially different founder prompt and stop at human review.

## Project entry and evidence-backed promotion

The Scout is also available outside fixed calibration cases through
`/vision-scout <context>`. It enriches that user request with product alignment and bounded
workspace observation, stores the full context privately, and exposes only fingerprints in
the main record. A distinct request fingerprint makes repeated identical user requests
idempotent even when observation timestamps or Palamedes state files have changed.

Full Genesis promotion is a separate command and artifact. Two distinct independent human
reviewers must both prefer or tie the Scout prompt, report confidence of at least 60, and
leave no mean review axis more than five points below the hidden human reference. Model and
team reviews are recorded but cannot satisfy the gate. A passing gate runs Genesis once,
links the Scout and Genesis IDs, and leaves delivery authority false. This first promotion
path deliberately serves blinded Scout packets and does not infer renewal from the Scout's
own governor or model judge.

Project Scouts may instead preregister one behavioral probe. The plan fixes a single
numeric metric, operator, threshold, minimum sample of at least five, maximum 30-day
duration, and source before the outcome exists. The outcome accepts only measured or
external-dataset provenance, must meet the preregistered sample, is mechanically compared
with the threshold, and can be recorded only once. A passing result authorizes one full
Genesis; a failing result permanently blocks that behavioral renewal path. Neither result
authorizes delivery.

## First project-Scout failure

The first real-project invocation, session `palamedes-project-scout-live-001`, was not
retried. The originator response failed the exact source-quote attribution check before a
Scout record could be selected. This exposed two production gaps: project runs lacked the
benchmark's one-attempt ledger, and exact character matching rejected line-wrapped source
text. Project Scout now preregisters one attempt per request fingerprint, records failed
provider usage and error type, and blocks retries under the same Scout version. Source
validation now normalizes whitespace only; it still rejects paraphrases. Because the failed
live call predated that ledger, it is documented here rather than retroactively presented
as a registered trial or rerun for a favorable result.

## Real-project Scout V2–V4 chronology

V2 (`palamedes-project-scout-live-002`) consumed one registered attempt and failed exact
source-quote matching after 37,697 tokens. The failure showed that asking a model to copy
repository text exactly was an unnecessary generative responsibility. V3 replaced that
contract with deterministic source anchors: Palamedes extracts the exact text, the model
selects an anchor ID, and the system reattaches the quote. Invented IDs remain invalid.

V3 (`palamedes-project-scout-live-003`, scout `vision-scout-e42f93e21f7d`) completed all
three roles. Its selected founder prompt proposed an evidence-earning decision environment:
small reversible claims are put at risk, contradictions alter later questions, and changing
one's mind becomes competent progress instead of social defeat. The governor selected blind
human review and granted neither full Genesis nor delivery. The run used 122,709 tokens,
revealing that a three-role Scout was not yet low-cost when the project context itself was
86,210 characters.

V4 introduced source-preserving context compaction. User context, product ground truth,
gates, prior investment, and interpretation rules remain verbatim structures, while bounded
document headings/excerpts and repository state keep the provider context below 10 KB in the
large-workspace test. The live V4 originator and critic completed with 50,354 metered tokens;
the governor call failed without a usable diagnostic. A successful run was projected near
75k tokens, materially below V3 but still not a proven expected cost.

Palamedes now stores successful project-Scout role outputs, usage, and fingerprints as
immutable checkpoints. A runtime failure may resume at most twice, reusing completed roles
and invoking only the missing role. Contract or semantic-validation failures still consume
the one-shot attempt and cannot be retried creatively. The V4 outputs predated this feature,
so they were deliberately not reconstructed after the fact. V5 is the first eligible live
condition with checkpoint custody active from the initial call.
