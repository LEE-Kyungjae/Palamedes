# Palamedes 제품 개요

<p align="center">
  <a href="product-overview.md">English</a> · <strong>한국어</strong>
</p>

Palamedes는 `planner -> task -> implementation`보다 앞에서 작동하는 로컬 우선
미션 인텔리전스 계층입니다. 사람이나 에이전트가 무엇을 추구할 가치가 있는지,
왜 그런지, 어떤 증거가 결정을 뒤집을 수 있는지, 언제 재검토해야 하는지를
판단하도록 돕습니다.

## 존재 이유

실행 에이전트는 잘못된 목표를 매우 빠르게 구현할 수 있습니다. Palamedes는 방향을
일회성 프롬프트가 아니라 수정 가능한 상태로 다룹니다. 경쟁 해석, 증거, 가설, 관점
변화, 기각한 대안, 반증 조건과 복원 지점을 보존합니다.

## 계획 흐름

```text
세계 신호와 레퍼런스
  -> 관찰과 추론 분리
  -> 경쟁 해석
  -> 후보 미션과 기회
  -> 적대적 검토와 반증 조건
  -> 경계가 명확한 미션 계약
  -> planner -> task -> implementation
  -> 귀속 가능한 결과 신호
```

## 핵심 개념

- **작업보다 미션:** 일을 늘리기 전에 가치 있는 결과를 정합니다.
- **경쟁 해석:** 증거가 구분할 때까지 서로 다른 관점을 보존합니다.
- **증거와 가설 분리:** 높은 확신이 추론을 사실로 바꾸지는 않습니다.
- **관점 전환:** 무엇이 바뀌고 보이게 됐으며 새 관점이 무엇을 숨길지 기록합니다.
- **가역적 probe:** 권한을 넓히지 않고 학습을 만드는 행동을 선호합니다.
- **결과 계보:** 과거를 다시 쓰지 않고 승인된 미션과 결과를 연결합니다.
- **제한된 권한:** Palamedes는 제안하며 실행과 승인은 사람과 host가 가집니다.

## 제품 경계

Palamedes는 범용 실행 runtime, 자동 배포 도구, 일반 프로젝트 관리자, 창의성이나
사업 성공 보장 도구가 아닙니다. 미션, probe, 제품 기회와 검토 gate를 제안할 수
있지만 구현이 일어났다고 주장하거나 스스로 delivery 권한을 열 수 없습니다.

## 상태 모델

저장소 로컬 상태에는 현재 계획, 증거, 가설, 개발 probe, 관점 전환, 결정, revision,
outcome과 복원 정보가 포함됩니다. fingerprint는 오래된 쓰기가 최신 상태를 조용히
덮어쓰는 일을 막습니다.

안정성 등급은 [STABILITY.md](../STABILITY.md), 버전 정책은
[CONTRACT_VERSIONING.md](../CONTRACT_VERSIONING.md)를 참고하세요.

## 대상 사용자

창업자, 제품 팀, 연구자, 에이전트 host처럼 비싼 구현 전에 판단 근거를 확인해야 하는
사용자에게 적합합니다. 가능한 방향이 여러 개이거나 실행 속도가 빠르며 upstream
결정과 downstream 결과 사이의 피드백이 약한 프로젝트에서 특히 유용합니다.

## 설계 원칙

1. 더 큰 작업 목록보다 가치 있는 미션을 먼저 정합니다.
2. 해석보다 관찰을, 조기 수렴보다 대안을 우선합니다.
3. 검색량이 아니라 실제 영향을 기록한 레퍼런스를 사용합니다.
4. 불확실성, 반증 조건, non-goal과 reversal trigger를 명시합니다.
5. 증거 압력을 통과한 가장 단순한 메커니즘을 선택합니다.
6. 추천 강도는 증거 강도를 넘지 않습니다.
7. 더 많은 텍스트보다 더 나은 외부 결정을 평가합니다.

인지 경로는 [인지 워크플로](cognition-workflows.ko.md), 현재 증거의 한계는
[증거와 데모](evidence-and-demos.ko.md)를 참고하세요.
